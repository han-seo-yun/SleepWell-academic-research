# 실제 CMI·MESA 에이전트 협업 실행 결과

2026-11-07, E 드라이브 SleepWell Research의 실제 제공자 연결과 로컬 모델 실행 서비스를 사용했다. 원본 episodes.csv의 SHA-256이 실행 전후 일치하며 모든 실험의 `input_synthetic=false`, 원래 분할 `train`을 확인했다.

| 자료 | 실제 입력 범위 | 완료 역할 | 기록된 역할 간 전달 | 보고서 자동 검사 |
|---|---|---:|---:|---|
| CMI | 10명·323밤 | 7개 | 6개 | 오류 0건 |
| MESA | 10명·70밤 | 5개 | 2개 | 오류 0건 |

CMI는 데이터 분석 → 모델 설계 → 실제 학습·검증 → 결과 검수 → 성능 분석·지침 검토 → 보고서 작성을 실행했다. 내부 검증 63밤과 마지막 평가 42밤을 사용했다. 결과 검수의 변경 요청 2건은 저장됐지만 보고서 예산 확보(`report_budget_reserved`)에 따라 추가 설계 라운드는 실행하지 않았다. 따라서 재설계 경로는 점선이다. 이 경로에서 호출하지 않은 별도 실험 계획 역할도 실행 기록 없음으로 남겼다.

MESA는 실험 계획, 설치된 4개 MESA 모델과 Recent-7 비교 실행, 성능 분석, 지침 검토, 보고서 작성을 완료했다. 공통 비교는 10명·60밤이다. 자율 설계의 최소 시간 구간 조건을 충족하지 않아 기존 모델 비교 경로를 사용했다. 계획 ID가 실행 설정에 소비된 사실은 확인했으나 역할 간 전달 trace가 없는 계획→실행 선은 실선으로 만들어 넣지 않았다.

창 오른쪽 위의 실선 범례는 **실제 실행된 기록**, 점선 범례는 **가능한 협업 경로**다. 완료된 역할의 카드는 해당 실행의 구조화된 결과를 이용해 각각 다른 짧은 요약을 표시한다. 실제 전달 내역은 라운드와 실행 ID에 연결되며 상세 근거 탭에서 확인할 수 있다.

## 저장 파일

- `CMI/CMI_실제협업.swa`: CMI 프로젝트. 실제 작업 지시와 대화, 모델 실행, 협업 trace, 보고서를 포함한다.
- `CMI/CMI_실제협업흐름.png`, `.svg`: CMI 협업 흐름.
- `MESA/MESA_실제자료_협업.swa`: MESA 프로젝트.
- `MESA/MESA_실제자료_에이전트협업.png`, `.svg`: MESA 협업 흐름.
- 각 폴더의 `작업지시.txt`: 실제 제출한 작업 지시.
- `verification.json`: 원본·입력 해시, 실제 실행 ID, 보고서 검사, 최종 카드 설명 검증 결과.

이 폴더의 **CMI 실제 협업 열기.lnk** 또는 **MESA 실제 협업 열기.lnk**를 실행한 뒤 **에이전트 협업**을 누르면 같은 기록을 확인할 수 있다. CMI 결과는 앱 창에도 열어 두었다.

## 해석 범위와 검증

전체 코호트 실험이 아닌 원래 train 참여자의 제한된 탐색 표본이다. CMI는 기록이 긴 참여자를 선택한 편향이 있으며, 두 결과 모두 독립 test 평가가 아니다. 보고서의 수치·출처 자동 검사는 통과했으나 의미 해석 및 지침 체크리스트의 최종 판단은 사람 검토 대기로 기록돼 있다.

협업 흐름 데이터·그림·UI 테스트 16개, 협업 실행·보고서·개발 워크플로 관련 테스트와 수정 Python 파일 컴파일 검사를 통과했다. 과거 실패 시도는 각 `attempt_*` 폴더 및 프로젝트 trace에 별도로 보존했다.

앱 수정 파일: `researchbench/agent_flow_data.py`, `agent_flow_plotting.py`, `collaborative_harness.py`, `report_agents.py` 및 관련 테스트. 재현·검증 스크립트는 앱의 `tmp/agent_collaboration_real_20261107/`에 있다.

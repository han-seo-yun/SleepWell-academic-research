# DATA33 누적 경로와 희망 수면시간 직접 입력

> 이 문서는 11/05의 직접 일지·희망 수면시간 변경 당시 기록입니다. 같은 날 후속 요청으로 **워치 자동 누적·DATA33·개인화 입력이 확장**되었습니다. 아래의 일지 전용/자동 수집 설명보다 [후속 구현 기록](WEARABLE_PERSONALIZATION_2026-11-05.md)이 우선합니다.

## 확인 결과

직접 작성한 수면일지는 앱 전용 `filesDir/sleep_diary.json`에 누적 저장된다. 새 기상 날짜의 일지를 저장하면 기존 날짜들은 유지되며, 같은 한국 기상 날짜는 기존 일지의 수정으로 처리한다. 앱 재실행과 매 분석에서 파일을 다시 읽는다. 따라서 저장한 기록이 늘면 DATA33과 개인화 입력에도 반영된다.

DATA33은 33개의 입력 특징을 뜻하며 33일 기록을 요구하지 않는다. 원 일지를 보관하고 분석 때 특징을 재계산하는 구조다. 전체 특징 벡터를 매일 별도 파일로 누적 저장하거나 기기에서 학습 모델을 재훈련하는 기능은 아니다. 현재 저장 결과에는 예측·권장 요약이 저장되며, 과거 DATA33 전체 스냅샷의 시계열 보관은 제공하지 않는다.

| 단계 | 구현 | 동작 |
| --- | --- | --- |
| 직접 입력 | `ui/AnalysisScreen.kt`, `analysis/DirectInputParser.kt` | 누운 시각·최종 기상과 선택 측정값을 입력하고 `입력 반영해서 다시 분석`으로 저장 |
| 영속 저장 | `analysis/DiaryStore.kt` | 날짜별 ID 병합, atomic JSON 저장, 늦게 저장된 수정본보다 오래된 수정 거부 |
| 앱 재진입·재분석 | `AnalysisScreen.runAnalysis` | 저장된 일지를 다시 로드 |
| 모델 입력 | `analysis/NextNightModel.kt`, `user/UserModelEngine.kt` | 직접 일지를 주 입력으로 사용하며 워치 관측은 보조로 구분 |
| 특징 계산 | `user/PortableFusionModel.kt` | DATA 15+18=33개, HYBRID는 물리 특징 6개를 더한 39개 |

## 기록이 늘 때의 계산

- 최근 28일 중 최대 7개: 최근·직전 취침/기상, 수면 구간, 변동성, 기록 수·신선도.
- 최근 56일 중 최대 14개: 중앙값, 시간 가중값, 평일/주말 특성, 변동성·추세·기록 간격.
- 전체 유효 기록 수 `n`: gradual_v1 개인화 비중 `n/(n+14)`. 예: 1개 약 6.7%, 14개 50%, 30개 약 68.2%.
- 집단 기준과 달력 특징도 DATA33에 포함된다. 기록이 없으면 집단 기준으로 계산하며 첫 유효 일지부터 점진적으로 반영한다.
- 위 비중은 융합 행동 예측의 비중이다. 별도 추천 목표 조정에는 측정 완전성·개운함·피로도·시간 경과에 따른 유효 근거량 등의 추가 조건이 있다. 기록 개수만으로 목표가 반드시 바뀌는 것은 아니다.
- 미래 기록, 예측 기준 이후 입력된 일지, 잘못된 시간 구간은 해당 기준의 특징에서 제외된다. 연구 기준 시각은 20:00 Asia/Seoul이며 표시 시간대 자동 연동과 구분한다.

## 자동 수집 범위

- 앱 자체가 사용자의 수면을 자동 감지하지 않는다. DATA33의 현재 주 입력은 직접 저장한 일지다.
- Health Connect는 권한이 있으면 분석 화면 진입 시와 불러오기 버튼에서 조회한다. 백그라운드 주기 수집은 없다.
- Health Connect의 최근 30일 조회 결과는 기존 저장 기록과 병합하므로 이미 받아 둔 이전 기록은 유지된다. 워치 기록만 늘어난 경우 이를 직접 일지로 간주해 DATA33을 늘리지는 않는다.
- 하루 여러 수면을 별도 주 수면일지로 저장하거나 직접 일지 목록에서 삭제·내보내는 전용 화면은 아직 없다. 낮잠은 별도 컨디션 입력이다.

## 이번 변경

- `ui/ProfileEditor.kt`: 희망 수면시간 선택 칩을 시간·분 숫자 입력란으로 교체. 예를 들어 7시간 45분을 입력할 수 있다.
- `analysis/ProfileStore.kt`: 직접 입력 문자열을 기존 420~540분 계약으로 검증. 분은 0~59이며 잘못된 입력은 저장하지 않는다.

- 기존 수면 기록, 모델 가중치, 특징 순서와 연구 정책은 변경하지 않는다.

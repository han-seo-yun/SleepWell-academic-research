# 통합 v7 — 프론트엔드 및 기존 기능 연동 검증

작성일: 2026-11-05. 앱 ID `app.sleepwell`, versionCode `7`, versionName `0.7.0`.

## 적용 내용

- 오늘: 권장 취침·목표 기상, 연결 상태, 최근 주 수면, 현재 기기 날짜 기준 최근 7일 요약, 목표·컨디션 입력, 펼칠 수 있는 상세 분석.
- 입력·연결: 별도 하단 시트에서 편집. 회전 및 오늘/기록 화면 이동 시 입력 초안 유지. 프로필 편집도 회전 시 유지.
- 최초 설정: 성별·연령대·직업군 → 수면 습관의 2단계. 희망 수면시간은 기존 7~9시간 범위에서 시간·분 직접 입력.
- 기록: 삼성 헬스/Health Connect·수동 일지를 기상일별로 통합. 같은 밤은 수동 일지 우선. 기존 정책에 따라 3시간 이상 주 수면을 보여주며, 수집 원본 자체는 별도 보관.
- 삼성 헬스/Health Connect 우선 불러오기. 파일과 직접 일지는 사용자가 선택할 때만 추가. 사용자 화면의 합성 데이터 실행 버튼·합성 설문 주입 경로를 제거. 기존 Test 기록과 개발용 자산은 삭제하지 않고 일반 기록·내보내기·새 개인화 입력에서 제외.
- 실기록이 없으면 초기 습관 기반임을 안내. 수면 시각만 있는 기록에서 수면 단계나 점수를 만들어 내지 않음. 출처는 삼성 헬스·일반 Health Connect·직접 기록으로 구분.
- 시스템 다크 모드, 현재 기기 시간대, 그래프 대비, 시각 선택 버튼의 접근성 이름을 적용. 목표 기상 입력은 시스템 알람을 설정하지 않음.

## 유지되는 경로

Health Connect → `SleepDataStore`/`ImportedSleepStore` → 실제 사용자 설문 보완 → `NextNightModel` → DATA33·점진 개인화 → 화면.

닫힌 앱에서는 기존 `SleepSyncJobService`/JobScheduler가 같은 저장소에 누적하며 다음 분석이 파일을 다시 읽는다. 약 1시간 간격의 백그라운드 작업은 Android 실행 여건과 별도 권한에 따르며, 강제 종료 후에는 앱을 다시 열어야 한다. 앱 화면의 자동 조회는 진입·복귀 및 사용 중 15분마다 수행한다.

앱 ID, 저장 형식, 모델 가중치와 학습 방식은 변경하지 않았다. 모델/health 코드·자산 및 핵심 저장·설문·백그라운드 파일 총 42개를 v6와 바이트 비교하여 동일함을 확인했다. DATA33 진단 스냅샷의 39개 값은 DATA33 33개와 물리 특징 6개의 조합이며, 수면 기록 누적은 모델 재학습을 뜻하지 않는다.

## 검증 결과

- APK 및 계측 테스트 APK 빌드 성공.
- 계측 회귀 테스트 **114개 통과**: 기존 109개 + 기록 병합/출처/시간대 3개 + 첫 실행/메인 화면 실행 2개.
- 회귀 범위: 수면 자동 누적·중복/수정 처리, 30일 이전 이력 보존, DATA33 입력 개수, 개인화 정책과 기준 모델 일치, 결측 측정값/설문 연결, 시간대·관측 시점, 권한 취소/실패/취소 처리, 동시 저장, 주 수면 표시.
- 첫 실행과 프로필 완료 후 메인 화면이 실제 Activity로 실행·렌더링됨을 검사했다. 사용자 저장소에 합성 수면을 넣지 않았으며 임시 테스트 프로필은 원래 바이트로 복구했다.
- 앱 프로세스가 없는 상태에서 별도 JobScheduler probe(53100)가 `SleepSyncJobService`를 새 프로세스로 실행한 것을 확인. 실제 Health Connect 읽기는 `EMPTY`로 정상 완료. probe 예약은 이후 취소했다. 일상 예약 ID 53001은 유지.
- 기존 사용자 프로필·설문·저장 결과의 바이트 보존 확인. 업그레이드 직후 파일 4개가 모두 동일했으며 실행 후 Android ProfileInstaller의 `profileInstalled` 표식만 갱신됨. 신규 파일은 정상 백그라운드 상태 기록이며 합성 수면 자료는 추가되지 않음.
- 최종 lint 오류 0개. 기존 코드의 locale·아이콘·백업 규칙 등 경고는 검증 로그에 남겼다. OneDrive가 생성 캐시를 잠근 경우 해당 build 캐시만 정리하고 재실행했다.

근거: `verification/v7_final_instrumentation_2026-11-05.txt`, `v7_release_lint_2026-11-05.txt`, `v7_core_integrity.json`, `v7_data_preservation.json`, `v7_runtime_2026-11-05.json`.

## 확인 범위와 한계

연결된 기기는 Android 에뮬레이터 1대이며 삼성 헬스 실계정의 수면 기록이 없다. 따라서 실제 사용자의 삼성 헬스 데이터가 들어왔다고 주장하지 않는다. 수면 읽기/백그라운드 권한이 있는 이 에뮬레이터에서 빈 결과 처리와 서비스 실행을 확인했고, 자동 누적 후 모델 반영은 사용자 저장소와 분리된 테스트 fixture로 검증했다.

컴퓨터 화면 도구는 연결 시간 초과 후 최소화된 에뮬레이터 창을 취득하지 못했다. 실제 화면의 시각적 점검과 직접 터치 흐름은 이번 검증에서 완료하지 못했다. 대신 실제 Activity 실행·렌더링 계측 테스트와 실행 로그를 확인했다. 최종 앱은 원래 사용자 프로필 상태로 실행하며, 기본정보가 미완료이면 최초 설정부터 표시된다.

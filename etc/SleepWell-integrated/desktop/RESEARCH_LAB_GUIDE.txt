SleepWell 연구자용 0.6.6 — 통합 연구 분석실

SleepWell(Windows의 SleepWell.exe, macOS의 SleepWell.app)로 실행한 메인 연구 화면의 '연구 분석실'을 누릅니다.
연구 분석실은 별도 Python 설치나 연구용 venv 없이 배포본에 포함된 런타임으로 실행됩니다. 같은 데스크톱 프로세스가 별도의 loopback 포트를 관리하며, SleepWell을 종료하면 분석실 서버도 종료됩니다.

현재 엔진·평가 계약(2026-11-01)
- 추천 엔진: sleep-opportunity-v7-measurement-evidence / personalization-v5-measurement-evidence. 명시적 입면 또는 입면잠복기가 없으면 취침을 입면으로 대체하지 않으며, 입면잠복기·중간각성 구성요소가 불완전한 수면시간은 결측으로 유지합니다.
- 연구 추론: robust-next-night-research-v2+gradual_v1. 첫 유효 기록부터 n/(n+14)로 갱신하지만 저장된 legacy14 Test 지표는 이 런타임 정책의 검증값이 아닙니다.
- 사전 모니터링: prospective-behavior-v4-locked-monitoring. 등록 다음 20시부터 calibration 30일과 held-out 30일을 고정하고, calibration 적격 결과가 20건 이상일 때만 recent_adaptive의 입면·기상 결합 90% 예측구간을 동결합니다. 무작위배정·권장 효과·치료효과 추정이 아닙니다.
- 병렬 센서 S: research_shadow_sensor_s_v1. 20시까지 완료·수신된 연속 5분 관측과 검증 보정된 확률이 명시적으로 들어온 연구 실행에서만 확률 경로를 선택합니다. 공백·미보정·불확실성 초과 시 일지 S로 돌아가며 일반 실행은 센서 관측을 자동 생성하지 않습니다.
- 추천 시점: recommendation-timing-v1. 예상 입면 2시간 전과 20시 중 이른 시점의 최초 후보와 20~23시 조건부 갱신이며, 신선한 각성 관측이 없으면 갱신하지 않습니다.
- 분석실 입력 한도: 최대 365행, 10명, 2 MiB. 입력은 메모리에서 평가하고 자동으로 사용자 DB·모델·추천 정책에 쓰지 않습니다.
- /api/v1은 같은 참여자별 읽기 전용 스냅샷을 사용합니다. API 조회나 분석실 불러오기는 평가 실행이 아니며, 화면에서 연구자가 직접 실행해야 결과가 생성됩니다.

기존 버전이 이미 실행 중이라면 제어창 또는 알림 영역의 '종료'로 완전히 종료한 뒤 새 버전을 실행하세요. 창의 X 버튼은 알림 영역으로 숨기기만 합니다. 기존 DB 경로와 수동 기록·휴대폰 백업은 그대로 유지됩니다.

가상 데이터 확인:
- '가상 데이터' 선택, CMI와 MESA 모두 체크, 기본값으로 '현재 입력 평가'.
- 기본 42행 중 공통 평가 41밤, 모델 지표 9개, Matplotlib 그래프 8개(모델 진단 6개 + 관측 데이터 2개).
- '입력 변경 후 자동 재계산'을 켜고 시드·위상 이동·결측·보고 지연을 변경합니다.
- 같은 입력·시드의 예측과 지표는 같습니다. 합성 결과는 실제 정확도 근거가 아닙니다.

실제 자료 확인:
- 분석 원천에서 현재 PC 참가자 또는 연결된 휴대폰을 선택하고 '연동 기록 불러오기'를 누릅니다. 참가자 자료는 합치지 않습니다.
- 수면과 걸음·운동·카페인·일정·낮잠의 수신 건수, 20시 이전에 사용할 수 있었던 야간별 수치를 확인할 수 있습니다.
- 히트맵은 모델×참가자별 공통 야간 MAE, 박스플롯은 참가자별 공통 야간 평균 오차 분포, 편향 그림은 입면·기상 예측의 빠름/늦음을 표시합니다.
- 생활 정보는 조건별 분석용이며 현재 동결 모델의 입력이나 가중치를 바꾸지 않습니다. 카페인·일정은 SleepWell 직접 입력 기록입니다.
- 과거 PC 생활 정보에 참가자 귀속 정보가 없는 경우 혼합을 방지하기 위해 제외합니다. 새로 저장하는 생활 정보에는 현재 참가자 식별자가 기록됩니다.
- 'CSV 스키마 받기'로 양식을 확인한 후 '실제 후향 입력'에서 CSV 또는 JSON 배열을 넣습니다.
- participant_id는 연구 ID로 사용하고 시각에 시간대를 포함합니다. 관측·수신시각을 임의 생성하지 마세요.
- 예측 기준은 20:00입니다. 늦게 관측된 입력은 해당 시점의 과거 이력으로 사용할 수 없습니다.
- 정답 없는 입력의 정확도는 계산 불가로 남습니다. 결측을 0으로 채우지 않습니다.
- 기준선은 최근 28일 내 마지막 7회 관측 중앙값입니다.
- '그림 참가자'는 그림만 변경하고 전체 동일밤 비교 표본을 바꾸지 않습니다.

안전·해석 경계:
실제 입력은 로컬 메모리에서 평가하며 기존 프로필·원본 DB·제품 추천 정책에 저장하지 않습니다. JSON·논문용 그림 묶음 저장은 명시적 사용자 동작으로만 수행합니다. 원자료는 배포본에 포함되지 않습니다.
동결 연구 모델의 개인화 상태 갱신은 개인 생리상수 추정이 아닙니다. 후향 재생과 합성 예제는 새로운 미래 성능이나 추천의 인과효과를 검증하지 않습니다. PCR 모델은 포함하지 않습니다.

배포 파일:
Windows: SleepWell-<버전>-win-x64.zip(전체 압축 해제 후 SleepWell.exe) 또는 SleepWell-Setup-<버전>-x64.exe. 기존 설치를 자동으로 덮어쓰지 않습니다.
macOS: SleepWell-<버전>-mac-arm64.dmg(Apple 실리콘) 또는 -mac-x86_64.dmg(Intel). 응용 프로그램 폴더로 옮긴 뒤 실행합니다.


0.4.7 연구 화면과 논문용 그림
- 현재 연구 예측과 분석실은 첫 유효 기록부터 n/(n+14)로 개인화를 적용합니다. 기록 1개는 6.7%, 7개는 33.3%, 14개는 50%입니다. 14는 초기값의 가중치이며 대기 기간이 아닙니다.
- 아직 가용 기록이 없는 첫 예측은 초기값을 사용합니다. 미래 수면이나 늦게 보고된 기록을 미리 사용하지 않습니다. 일일 추천도 첫 기록부터 점진 반영하며 최근성에 따른 유효 기록 수를 사용합니다.
- 기존 동결 학습 가중치는 유지했고 추론 정책만 gradual_v1으로 구분했습니다. 저장된 legacy14 Test 지표는 새 정책의 성능 검증이 아닙니다. 새 예측은 이전 정책과 구분하여 저장하며, 분석실·시연 지표는 새 정책으로 다시 계산합니다.
- 본 화면은 등록 모델의 보존된 검증 결과, 연구 분석실은 현재 입력의 후향 재생 결과입니다. 두 결과의 표본과 의미는 다릅니다.
- 연구 분석실 상단의 연구자 홈 링크로 돌아갑니다. 연구분석실_실행.cmd도 통합 앱을 통해 분석실을 열어 동일한 홈과 자료를 사용합니다.
- 모델 해시, 전체 지표와 개인화 내부 값, 생활 맥락 가용성은 재현·진단 상세에서 확인합니다. 생활 맥락은 현재 예측 모델의 추가 입력 또는 효과 추정이 아닙니다.
- 평가 후 '논문용 그림·데이터 받기'로 벡터 PDF·SVG, 300 DPI PNG, source-data.csv, 결과 JSON, 그림 manifest, Python 재생 코드를 함께 저장합니다.
- 그림의 표본 단위는 참가자입니다. 같은 참가자의 여러 밤을 독립 표본으로 세지 않습니다. 참가자 수가 1이면 참가자 bootstrap 신뢰구간을 만들지 않으며, 소수 참가자의 구간은 불안정할 수 있습니다.
- 합성 데이터 그림은 기능 설명용임을 표시합니다. 후향 재생 그림을 전향 검증 결과로 해석하지 않습니다.
- 이 형식은 특정 학술지 제출 규격의 인증이 아닙니다. 최종 투고처의 열 너비·글꼴·파일 규격에 맞춰 확인하세요.

0.5.0 관측 데이터 진단과 배치 실행
평가 결과의 '관측 데이터 진단'은 입력된 관측 수면 자체를 기술합니다. 모델 예측과 독립적으로 계산하며 정확도·임상 지표·추천 효과가 아닙니다. 모델 비교 표와 run_id는 바뀌지 않습니다.
- 수면 규칙성: SRI(Sleep Regularity Index, -100~100; 24시간 간격 같은 분의 수면·각성 일치도), IS(일간 안정성)·IV(일내 변동), 평균 입면·기상·중앙시각과 표준편차, 주말(금·토 20시 기준일)−주중 중앙시각 차.
  · 각 관측 행의 20시부터 24시간을 1분 단위로 보고, 관측 주 수면 구간만 수면으로 둡니다. 낮잠은 입력에 없어 반영되지 않습니다.
  · 결과 없는 밤과 행 없는 날은 각성이 아니라 '모름'으로 두고 해당 비교 쌍을 제외합니다.
  · SRI는 연속 관측 밤 쌍 7개 이상, IS·IV는 관측 밤 7개 이상일 때만 계산합니다. 부족하면 계산 불가 사유를 표시합니다.
  · IS·IV는 수면 이진값 기반이므로 활동량(count) 기반 IS·IV 값과 직접 비교하지 마세요. 주말−주중 차는 근무 일정을 모르므로 사회적 시차의 근사입니다.
- 데이터 완결성·입력 시점: 참가자×기준일 격자로 '다음 20시 전 입력', '다음 20시 이후 입력', '예측만', '행 없음'을 구분합니다. 늦게 입력된 밤은 다음 날 예측 이력에 쓰이지 않았다는 뜻입니다. 입력 지연(관측시각−기상)은 중앙값·90% 백분위로 요약합니다.
- 그림: 이중 플롯 수면 액토그램(선택 참가자, 연속 이틀 폭; 주황 선은 융합 모델 예측 구간)과 데이터 완결성 히트맵이 추가되었습니다. 논문용 그림 묶음과 source-data.csv에도 포함됩니다.

배치 실행(CLI)
GUI 없이 같은 엔진으로 평가하고 결과 폴더를 만듭니다. 출력 폴더는 비어 있어야 하며 그 밖의 위치에는 쓰지 않습니다.
  python research_lab_cli.py --csv rows.csv --cohorts cmi,mesa --out 결과/run1
  python research_lab_cli.py --request SYNTHETIC_시연설정.json --out 결과/demo
결과: run.json(run_id·모델 해시·입력 SHA-256·명령·소요 시간), result.json, metrics.csv, observed_regularity.csv, observed_completeness.csv, figures.zip.
배포본 안의 런타임으로 실행할 때: Windows는 runtime\python.exe app\web-app\research_lab_cli.py …, macOS는 SleepWell.app/Contents/Resources/runtime/bin/python3 SleepWell.app/Contents/Resources/app/web-app/research_lab_cli.py … (PYTHONPATH에 app/vendor 지정).

설계 참고(코드 복사 없음, 지표 정의·화면 구성만 참고)
- SRI: Phillips AJK et al. (2017) Sci Rep 7:3216; 공개 구현 sleepreg(Windred et al. 2021, UK Biobank)과 GGIR.
- IS·IV: Witting W et al. (1990) Biol Psychiatry 27:563–572; pyActigraphy(Hammad et al. 2021), GGIR.
- 이중 플롯 액토그램: GGIR·pyActigraphy의 표준 시각화.
- 완결성 격자: Beiwe(Harvard Onnela Lab), RADAR-base, ActiGraph CentrePoint의 참여자 순응도 화면.
- 배치 실행·실행 기록: Luna(NSRR)와 GGIR의 스크립트형 재현 방식.


0.6.0 통합 연구자 앱
- 메인 화면과 연구 분석실을 하나의 사이드바 앱으로 합쳤습니다. 분석실은 앱 안에 열리며(별도 로컬 포트, 이 앱 주소에서만 임베드 허용), 참여자 화면의 '연구 분석실에서 분석'은 해당 참여자 기록을 분석실에 읽기 전용으로 불러옵니다. 평가는 연구자가 직접 실행합니다.
- 대시보드·참여자 화면은 분석실과 같은 참여자별 스냅샷을 사용합니다. 경고 기준: 마지막 기록 3일 이상, 최근 14일 관측 50% 미만, 다음 20시 이후 입력 30% 초과, 휴대폰 동기화 2일 이상.
- 로컬 읽기 API: /api/v1(색인), /system, /overview, /participants, /participants/{id}, /participants/{id}/records.csv, /openapi.json. 127.0.0.1에서만 응답하며 쓰기는 화면의 CSRF 보호 경로만 사용합니다.
- 화면 테마(라이트·시스템·다크)는 메인 앱과 분석실에 함께 적용됩니다.
- 설계 참고: Lunascope(엔진 위 단일 GUI), mindLAMP·Beiwe(연구자 대시보드와 참여자 순응도), RADAR-base(버전 관리된 읽기 API).

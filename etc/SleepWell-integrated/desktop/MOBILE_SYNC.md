# SleepWell 휴대폰 연결 — Windows 0.4.7 / Android 0.4.5

현재 코드 대조: 2026-11-01.

현재 저장소에는 수면 `/v1/sync` 송신, 사용자 상태 `/v1/backup` 송신, 걸음·운동·직접 입력 생활 맥락 `/v1/context` 송신 코드가 있다. 다만 생활 맥락은 Android가 스키마 1을 보내고 `web-app/mobile_context_store.py`가 스키마 2와 추가 `details` 필드를 요구하며, 저장소 안에 `/v1/context` HTTP 수신 라우트도 없다. 따라서 Windows 0.4.7과 Android 0.4.5의 **수면 동기화/백업**과 **생활 맥락 종단간 연동**을 같은 완료 상태로 표시하지 않는다.

삼성헬스의 Health Connect 걸음·운동 제공과 SleepWell의 해당 읽기 권한은 생활 맥락 송신에 필요하다. 권한은 휴대폰 사용자가 선택하며 일부 권한이 없으면 해당 범위를 완료 조회로 표시하지 않는다. 현재 소스에서는 걸음·운동·카페인·일정·낮잠의 PC 반영을 검증 완료 기능으로 사용하지 말고, 아래 차단 사항을 해결한 빌드에서 다시 확인해야 한다.

카페인·일정·낮잠은 SleepWell에서 작성한 기록이다. 삼성헬스나 휴대폰 캘린더에서 자동 추정하지 않는다. 의도된 계약은 최근 30일 범위에서 수정·삭제와 반복 전송을 구분하고, PC가 처음 받은 시각을 `available_at`으로 사용해 **연구 분석실 → 분석 원천 선택 → 연동 기록 불러오기 → 현재 입력 평가**에 전달하는 것이다. 현재 앱 화면이나 문서에 이 경로가 보이더라도 위 스키마 차단이 해결되기 전에는 종단간 성공을 전제하지 않는다.

수신 건수 0은 측정값 0을 뜻하지 않는다. 권한 부재, 조회 실패, 송수신 스키마 거절도 구분해야 한다. 분석은 20시 전에 PC가 처음 수신한 정보만 해당 밤의 생활 정보로 사용할 수 있다. 오늘 처음 가져온 과거 기록은 과거 예측 시점에 알려졌던 정보로 소급하지 않는다. 동결된 수면 예측모델은 추가 생활 변수를 학습하지 않았으며 생활 맥락은 조건 분석 후보일 뿐이다.

Android는 사용자용, Windows는 연구자용입니다. Android 14 이상과 Windows 10/11 x64를 대상으로 합니다. 휴대폰은 PC 없이 내장 CMI·MESA 데이터/수리·융합 모델을 실행해 수면 시각 예측과 권장 일정을 제공합니다. 연구 모델은 실제 행동을 예측하며, 권장 일정의 건강 개선 효과를 증명한 모델은 아닙니다.

## 연결과 일일 백업

1. Windows 배포본을 전체 압축 해제하고 `SleepWell.exe`를 실행합니다. 휴대폰 연결 영역에서 PC의 내부 주소를 선택하고 **연결 시작 / 새 코드**를 누릅니다.
2. 휴대폰에 사용자 앱 APK를 설치하고 시작 정보를 입력합니다. PC 연결 화면에서 일회용 연결 코드를 입력합니다. 코드는 10분간 한 번 사용하며 다른 사람에게 공유하지 않습니다.
3. 휴대폰에서 일일 자동 백업을 활성화합니다. 저장된 기록·프로필·추천·예측 스냅샷을 휴대폰에 암호화해 보관하고 연결 가능할 때 PC에 전송합니다. 수동 백업/전송도 가능합니다. 이 사용자 상태 백업은 Health Connect 새 기록을 자동으로 읽는 기능이 아니다.
4. PC가 꺼져 있거나 연결할 수 없으면 대기열을 보존합니다. PC 소프트웨어와 수신 연결을 켜고 같은 내부 네트워크에 연결하면 재시도합니다. 성공 응답을 확인한 해당 버전만 전송 대기에서 제거합니다.
5. Windows 화면에서 참여자별 수신 건수와 마지막 수신 시각을 확인하고 최근 백업 90건을 JSON으로 저장할 수 있습니다. 백업은 PC 현재 사용자의 일지를 덮어쓰지 않습니다.

Android의 백그라운드 실행 시점은 운영체제의 절전·실행 제한에 따라 지연될 수 있습니다. 정확히 같은 시각의 실행이나 매일 누락 없는 전송을 보장하지 않습니다. 강제 종료·전원 꺼짐·저장 공간 부족은 앱을 다시 열어 상태를 확인해야 합니다. 과거 날짜의 백업이나 예측을 실행된 것처럼 소급 생성하지 않습니다.

PC 재실행 후에는 수신 연결을 다시 켜야 합니다. 주소가 바뀌면 새 코드로 다시 연결합니다. 조직·게스트 Wi-Fi에서 기기 간 연결이 차단된 경우 이를 우회하지 않습니다. 공유기 외부 포트를 열거나 방화벽을 끌 필요가 없습니다. 방화벽 허용은 사용하는 개인 네트워크에 한합니다.

## 수면 기록 수집

삼성헬스가 Health Connect에 제공한 수면 세션·단계를 사용합니다. 삼성헬스에는 수면 쓰기, SleepWell에는 수면 읽기 권한이 필요합니다. 삼성 계정 비밀번호를 요구하지 않습니다.

수면 기록 읽기는 휴대폰 앱에서 사용자가 가져오기를 실행할 때 이루어집니다. 일일 백업 작업은 이미 휴대폰에 저장된 기록을 사용하며, Health Connect의 백그라운드 수면 읽기 권한을 추가로 요청하지 않습니다. 따라서 백업 자동화와 새로운 삼성헬스 기록의 자동 수집은 구분해야 합니다.

직접 작성한 일지와 주관적 개운함·피로도를 주 지표로 사용하고, 착용 상태에 영향을 받는 웨어러블 수면시각은 보조 지표로 표시합니다. 웨어러블에서 주관적 수면의 질을 만들어내지 않습니다. 앱은 센서로 수면을 직접 측정하지 않고 허용된 기록을 읽거나 사용자 입력을 받습니다.

수면 `/v1/sync`는 Samsung Health 출처의 최근 30일 완료 세션을 전송하며, 사용자 앱의 일일 `/v1/backup`은 `participant_key`별 사용자 상태를 별도 저장한다. 여러 참여자를 연구할 때는 참여자 식별자별 백업을 사용한다. PC는 수신 백업의 외부 형식·시간·용량을 검사하며, 내부 추천/예측/평가 값은 휴대폰이 보고한 원본 스냅샷으로 보관한다. 독립 재분석을 완료한 검증 결과로 취급하지 않는다.

## 생활 맥락 스키마 차단 사항

현재 종단간 검증 전에 맞춰야 할 계약은 다음과 같다.

1. Android `SyncRepository`의 `/v1/context` 요청을 PC 저장 계약의 `schema_version=2`로 올린다.
2. 모든 이벤트에 정확한 필드 집합을 보내고, 일정에는 `night_id`, `schedule_kind`, `preparation_minutes`, 낮잠·카페인에는 `night_id`를 `details`로 포함한다.
3. 인증된 기기 ID를 `mobile_context_store.ingest()`에 넘기는 `/v1/context` 수신 라우트를 구현하고 요청 크기·토큰·TLS 경계를 검증한다.
4. 전체 페이지 조회에 성공한 `steps`/`exercise`만 `complete_scopes`로 선언해 부분 실패를 삭제로 오인하지 않도록 한다.
5. Android 실기기 → Windows 수신 → 연구 분석실 `as_of` 조회를 한 흐름으로 테스트한다.

이 조건이 충족되기 전의 생활 맥락 전송 실패는 “관측 0”이나 모델 입력 0으로 바꾸지 않는다.

## 저장·접근 관리

휴대폰 기록·대기열과 연결 비밀키는 Android Keystore를 이용해 암호화하며 Android 자동 클라우드 백업에서 제외합니다. Windows 자료는 `%LOCALAPPDATA%\SleepWell`에 저장합니다. Google Drive나 다른 클라우드로 자동 업로드하지 않습니다.

수신 중지는 연결을 닫고, 등록 해제는 기존 접근 키를 무효화합니다. PC에 이미 받은 백업은 삭제하지 않습니다. 같은 버전 재전송은 중복 저장하지 않고, 같은 버전 내용 충돌은 거절합니다. 연결 인증은 일회용 코드와 휴대폰 접근 키, HTTPS 인증서 지문 확인을 사용합니다.

현재 배포본은 파일럿용이다. Windows 파일은 코드 서명 전이고 Android APK는 시험용 서명이다. Android `HealthConnectContextReader`는 U Extensions 7 API 사용에 대한 확장 SDK 가드가 없어 `lintDebug` 오류도 남아 있다. 실제 Galaxy 권한·절전 상태, 생활 맥락 스키마 수정본, 다른 PC의 방화벽 동작은 실기기 종단간 확인이 필요하다.

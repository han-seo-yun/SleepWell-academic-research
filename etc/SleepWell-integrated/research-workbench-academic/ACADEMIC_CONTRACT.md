# Academic desktop integration

The original `research_workbench` and canonical SleepWell source are read-only. This folder is an independent fork. Copied general tabular features remain available from a native window; startup opens the dedicated academic workspace.

Maintenance exception, explicitly requested 2026-11-04: literature-source comments in canonical `night_core.py`, `engine.py`, and `adaptive_personalization.py` and their exact vendor copies are updated together. The current source manifest records those comment changes; executable ASTs and numerical defaults remain unchanged. Historical run provenance and release artifacts are not rewritten. See [parameter evidence](../work/dayone-personalization-20261027/docs/PARAMETER_EVIDENCE_2026-11-04.md).

Canonical model/evaluation code: `work/dayone-personalization-20261027/web-app`, copied byte-for-byte to `vendor/sleepwell` with SHA256 manifest. Original APIs, model parameters, available-history cutoffs, time arithmetic, cohorts, evaluation denominators and personalization policies are preserved. Model inference is not relabeled as training. Stored validation reports are labeled historical evidence, never a fresh evaluation.

Backend: `academic_backend.run_research(config,progress=None,cancelled=None)` and `academic_prospective.run_prospective(config,progress=None,cancelled=None)` return JSON-compatible envelopes `{mode,raw,summary,provenance,warnings}`. Summary rows have `model_id,onset_mae_min,wake_mae_min,joint_mae_min,n_nights,n_participants` where computed. Missing metrics remain null. Mode-specific extra fields are retained. Raw original output is persisted intact. Cohort, source strata, retrospective/prospective status and synthetic status must stay visible.

Native persisted run: `{id,name,status,config,result,duration,created,error,traceback}`. Config contains input snapshot (records or synthetic settings), data SHA256, mode and budgets. Each run is immutable after completion. AcademicProject stores `project.json`, `runs/<uuid>.json`, immutable `inputs/` and an independent prospective journal. Resume converts unfinished run statuses to interrupted. One subprocess worker; parent writes run lifecycle; prospective worker commits append-only journal through its own atomic transaction. UI remains responsive and cancellation distinguishes requested from exited.

Plotting: `make_academic_figure(result,kind='comparison',metric='joint_mae_min',lang='ko',options=None)` and `export_academic_tables(result,path,lang='ko')`. Real original MAE values/denominators; no invented CI or common scalar across different evaluation problems. Options preserve manual title/annotation and font/size/dpi.

Prospective modes: `prospective_demo` is explicitly synthetic clock simulation, not future empirical validation. `prospective_commit` uses system time for generated_at and retains original eligibility window. `prospective_outcome` assesses an existing immutable forecast; no backdated actual forecasts. `prospective_summary` aggregates original-source assessments. Journal is project-local.

Ownership: leader owns Academic GUI, project/queue infrastructure, launch/install/package and end-to-end integration. academic_core owns vendor, academic_backend and backend tests. academic_prospective owns academic_prospective and tests. academic_plots owns academic_plotting, plot resources and tests. Preserve other agents' edits.

Prospective diary study (additive): `prospective_study`, `diary_server` and `prospective_study_ui` coordinate new study ledgers under `research/diary_studies/`. The existing participant journals and vendor inference remain unchanged. Main validation, feasibility and synthetic rehearsal are separate. Real collection is clock-driven; no backdated forecasts or hidden default-to-demo profile values. Governance declarations and consent are explicit, while actual institutional approval is not inferred from software fields. Mobile collection uses bearer tokens, withheld predictions and server receipts. External listening requires TLS; default loopback is a local preview. Aggregate reports retain missingness, uncertainty, frozen provenance and diary-only scope.

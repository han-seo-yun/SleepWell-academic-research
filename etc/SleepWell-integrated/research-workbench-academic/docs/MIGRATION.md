# 호환성, 이전 및 복구

## 형식 호환성

- 기존 SleepWell `.swa`는 schema 1 디렉터리 형식 그대로 읽는다.
- 기존 일반 프로젝트는 `format_version` 1 그대로 읽는다.
- 고도화 결과 원본은 프로젝트의 `research/` sidecar에 쓴다. 기존 `inputs/`, `runs/`, `experiments/`, vendored SleepWell 코드와 완료 결과는 변환하거나 덮어쓰지 않는다. `project.json`은 기존 저장 동작에 따라 선택한 페이지·언어·연결 경로 같은 UI 메타데이터와 저장 시각이 갱신될 수 있지만 schema와 실험 원본의 의미는 바꾸지 않는다.
- 일반 정형 데이터 프로젝트는 기존 네이티브 창에서 계속 관리하며 SleepWell 프로젝트에는 경로만 읽기 전용으로 연결한다.

따라서 필수 in-place migration은 없다. 처음 열기 전에 프로젝트 디렉터리 전체를 백업하는 것을 권장한다.

## 새 sidecar

대표적인 새 자료는 다음 위치에 저장된다.

- `research/evidence.sqlite3`: 프로젝트 범위 문서·청크·검색 감사
- `research/reports/*.json`: 불변 보고서 버전
- `research/run_evidence/<result_hash>.json`: 보고서에 고정한 검증된 run 근거 사본
- `research/exports/`: 사용자가 만든 내보내기
- 기타 고도화 평가/AI 감사 저장소

외부 일반 프로젝트 run을 보고서에 포함하면 canonical run을 현재 보고서 프로젝트에 고정한다. 원본 프로젝트와 source file 경로·해시는 provenance로 남는다. 원본이 접근 가능하면 변경을 검사하고, 이동 또는 오프라인으로 접근할 수 없으면 고정 사본 사용을 경고한다. 고정 사본은 새 계산이나 새 외부 평가로 표시하지 않는다.

## 프로젝트 복사와 이동

1. 프로그램을 종료해 실행 중인 작업과 SQLite 쓰기를 끝낸다.
2. `.swa` 디렉터리 전체를 복사한다. `research/`를 포함하면 보고서와 문서 인덱스도 함께 이동한다.
3. 새 위치에서 프로젝트를 열고 진단/자동 검사를 실행한다.
4. 로컬 문헌 원본이나 연결된 일반 프로젝트가 절대 경로에 남아 있으면 새 위치를 다시 연결한다. 과거 source ID/version/hash는 변경하지 않는다.
5. 원본 파일을 다시 연결할 수 없는 과거 보고서는 원래 locator를 보존하되 원문 열기 불가 상태를 표시한다.

다른 프로젝트의 `research/evidence.sqlite3`만 복사해 합치지 않는다. 프로젝트 ID와 접근 경계가 다르므로 문서 가져오기 기능으로 명시적으로 다시 등록해야 한다.

## 되돌리기

고도화 기능을 사용하기 전 상태로 되돌리려면:

1. 프로그램을 종료한다.
2. `research/` 디렉터리를 별도 위치에 백업한다.
3. 정확한 프로젝트 내부의 `research/`만 제거한다.
4. 기존 `.swa` 또는 일반 프로젝트를 다시 연다.

이 과정은 기존 실험을 제거하지 않지만, 백업하지 않은 문서 인덱스, 보고서, 검사·검토 기록과 고정 run 근거는 복구할 수 없다. 프로젝트 루트, `runs/`, `inputs/`, `experiments/`를 삭제하지 않는다.

## 버전 및 제한

- 보고서 스키마, 앱 버전, 템플릿·prompt 버전, 환경과 근거 해시는 manifest에 기록한다.
- 사용자 편집, 번역, 자동 검사, 사람 검토는 각각 새 보고서 버전을 만든다. 이전 버전을 덮어쓰지 않는다.
- 원본 데이터나 문헌 전문은 권한과 명시적 선택 없이 내보내기 패키지에 자동 포함하지 않는다.
- frozen external assessment는 별도 기능이며, 기존 결과를 외부 검증으로 승격시키는 migration이 아니다.
- 이전 버전 앱에서 `research/`를 무시할 수 있지만 새 보고서/근거 기능은 표시되지 않는다.

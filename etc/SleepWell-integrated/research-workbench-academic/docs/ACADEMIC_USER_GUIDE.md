# SleepWell 학술제 전용 사용 가이드

## 1. 근거 수준부터 확인하기

화면과 실행 기록은 다음 근거를 구분한다.

- **합성 시연**: `sleepwell_50days.csv` 또는 설정으로 생성한 자료. 프로그램 흐름과 계산 연결을 검증하지만 실제 연구 성능이 아니다.
- **새 후향 재생**: 사용자가 제공한 적격 기록에 원본 평가 코드를 실행한 결과다.
- **실제 전향 기록**: 결과를 알기 전에 시스템 시각으로 예측을 고정하고, 이후 관측값을 별도로 등록한 기록이다.
- **저장된 검증 근거**: 동봉된 과거 검증표다. 전체 원시 코호트가 없으므로 이 프로그램에서 새로 학습하거나 재평가한 결과가 아니다.
- **단일 예측·사전분포 선택**: 성능 평가가 아니며 MAE가 없을 수 있다.

후향, 실제 전향, 합성 시연의 MAE를 섞어 하나의 순위로 만들면 안 된다. CMI와 MESA도 서로 다른 기준 코호트임을 유지한다.

## 2. 50일 샘플로 전체 흐름 실행

1. `프로젝트 개요` → `학술제 50일 합성 샘플`을 선택한다.
2. `데이터·실험 설정`에서 입력 방식이 `불러온 기록`, 합성 표시가 선택되었는지 확인한다.
3. `후향·개인화·전향 시연 실행`을 선택한다. 묶음 예산은 최소 3개 실행이어야 한다.
4. `실행 대기열`에서 각 실행의 단계·경과 시간·완료 상태를 확인한다. 취소 요청과 실제 종료 상태는 구분된다.
5. `모델 성능 비교`에서 실행을 선택한다.

후향·개인화 결과에는 9개 비교군이 표시된다.

- CMI: 수리 고정, 수리 개인화, 데이터, 융합
- MESA: 수리 고정, 수리 개인화, 데이터, 융합
- 공통: 최근 7일 기준선

전향 합성 시연에는 13개 비교군이 표시된다.

- 프로필 기준, 최근성 적응, 맥락 후보
- CMI/MESA 각각 수리·데이터·융합
- CMI/MESA 데이터·융합의 온라인 개인화 비교 4개

온라인 개인화는 현재 또는 미래 결과를 사용하지 않고 이전 야간에 확정된 잔차만 사용한다. 향상을 보장하는 추천 모델이 아니라 추가 연구 비교군이다.

## 3. 실제 후향 자료

CSV, Excel 또는 JSON을 불러올 수 있다. 원본 파일은 수정하지 않고 프로젝트 `inputs/`에 CSV 스냅샷과 해시를 저장한다. 핵심 열은 다음과 같다.

```text
participant_id, cutoff, sleep_start, sleep_end, observed_at
```

시각은 timezone offset이 있는 ISO datetime을 사용한다. 결과를 알 수 있었던 `observed_at`이 cutoff 이후라는 원본 시간 계약을 지켜야 한다. 적격하지 않거나 결과가 없는 행은 0점으로 채우지 않는다.

`후향 평가`는 공통 야간의 원본 분모를 유지한다. `개인화 추이`는 같은 원본 실행에 기록된 개인화 가중치와 임계값을 보여준다. 이는 개인화 피처의 인과 효과를 뜻하지 않는다.

## 4. 실제 전향 예측과 결과 등록

`전향 예측·관측 기록` 화면에서 다음 순서를 지킨다.

1. 프로필 JSON과 과거 기록을 확인한다.
2. 대상 날짜를 선택하고 `실제 시각으로 예측 고정`을 누른다.
3. 고정된 forecast ID, 생성 시각, 20:00~20:15 수집 적격성을 확인한다.
4. 수면이 끝나고 결과가 확보된 뒤 forecast ID를 선택한다.
5. `sleep_start`, `wake`, `observed_at`, 출처를 입력하고 `관측 결과 등록·평가`를 실행한다.
6. `전향 기록 집계`로 사용자 보고와 보조 웨어러블 출처를 분리해 확인한다.

예측은 결과 등록으로 변경되지 않는다. 결과 평가는 append-only이고, 같은 결과의 재등록은 멱등 처리된다. 합성 전향 시연은 실제 journal에 넣지 않는다. 기본 합성 프로필이나 합성 이력으로 실제 전향 실행을 만들었다면 결과 화면의 합성 표시를 반드시 유지한다.

## 5. 원본 보고서 10종

`데이터·실험 설정`에서 보고서 모드를 선택한다.

| 보고서 | 실행/근거 | 추가 입력 |
|---|---|---|
| 수리모델 진단 (`research_diagnostics`) | 동봉 artifact 진단 | 없음 |
| 측정·데이터 품질 감사 (`measurement_audit`) | 제공 기록 집계 | `records`, `as_of`; 선택 `profile`, `snapshots`, `context` |
| 타깃 타당성 (`target_validity`) | 제공 기록 집계 | `records`, `as_of` |
| 휴대전화 기준선 (`phone_baseline`) | 동결 예측–최초 결과 쌍 재계산 | `outcomes`, `as_of` 필수 |
| 기존 야간 모델 (`night_model`) | 단일 예측 | `cohort`, `cutoff`, `records`, `profile` |
| 집단 사전분포 (`population_prior`) | 초기 사전분포 선택 | `profile` |
| 생리 상수 검증표 | 저장된 과거 근거 | 없음 |
| 전체 타당성 검증표 | 저장된 과거 근거 | 없음 |
| 개인화 검증표 | 저장된 과거 근거 | 없음 |
| 타깃 검증표 | 저장된 과거 근거 | 없음 |

`night_model`의 cohort는 `cmi` 또는 `samsung`이다. Samsung은 연결된 개인 이력을 요구할 수 있으며 프로필의 `link_history`와 기록을 함께 확인한다. 단일 야간 예측은 새 정확도 평가가 아니다.

고급 보고서 입력은 `원본 보고서 요청 JSON 불러오기`로 제공한다. 허용되는 최상위 필드는 다음뿐이다.

```json
{
  "records": [],
  "outcomes": {},
  "context": {},
  "snapshots": [],
  "profile": {},
  "as_of": "2026-11-01T20:00:00+09:00",
  "cutoff": "2026-11-01T20:00:00+09:00",
  "research_context": true,
  "personalization_policy": "gradual_v1",
  "cohort": "cmi"
}
```

휴대전화 기준선의 `outcomes`는 임의의 사후 예측값이 아니다. 원본 휴대전화가 미리 동결했다고 보고한 `prospective_forecasts`와 append-only 최초 자기보고 `prospective_outcomes`를 포함해야 한다. 유효한 동결 envelope, artifact identity, 시간 순서가 맞지 않으면 제외된다. 빈 `outcomes`로 성능 수치를 만들지 않는다.

## 6. 결과와 그림 내보내기

결과 화면에서 지표와 그림 종류를 선택한다.

- 모델 비교: 실제 기록된 MAE 막대. 원본에 없는 신뢰구간은 표시하지 않는다.
- 실제값·예측값: 20시 이후 분 단위의 기록된 값
- 개인화 추이: 원본 상태의 가중치 또는 임계값
- 야간별 오차: 야간별 실제 절대오차 분포
- 원본 보고서: MAE가 없는 보고서의 정규화 표

설정에서 자동 제목을 사용자 제목으로 바꾸거나 제목을 숨길 수 있다. 사용자가 쓴 제목과 주석은 언어 전환 시 덮어쓰지 않으며 `자동 문구로 복원`으로 되돌린다.

그림은 고해상도 PNG와 벡터 PDF/SVG, 표는 CSV/XLSX로 저장한다. 표에는 성능 요약, 예측값, 개인화, 모델 정보, provenance, 실행 메타데이터, 주의사항과 보고서 표가 포함된다.

## 7. 저장·복원과 검증

`.swa`는 파일 하나가 아니라 프로젝트 디렉터리다. 폴더 전체를 복사해야 입력·실행·전향 journal이 함께 이동한다. 실행 중 종료된 작업은 재열기 때 `중단됨`으로 표시한다.

개발·재현 검증 명령은 다음과 같다.

```powershell
.\.venv\Scripts\python.exe -m unittest discover -s tests -v
.\.venv\Scripts\python.exe .\scripts\verify_academic_release.py
```

검증 스크립트는 설치된 의존성만 사용하고 새 패키지를 설치하지 않는다. 기본 50일 합성 샘플에서 실행 기록, 그림, 표, manifest를 다시 만든다. 최종 통과 수와 실제 GUI 육안 확인 범위는 실행 후 [VALIDATION.md](../VALIDATION.md)에 기록한다.
